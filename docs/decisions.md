## Implementation decisions (Phase 0, Sept 21, 2026)

| Decision          | Choice and why                                                                                                                                                                                                                                                                                                                                                             |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Local database    | `npm run db:local` serves an embedded PGlite Postgres over the wire protocol on 127.0.0.1:5433. Next 16's dev server renders in several worker processes, which corrupts a file-backed PGlite opened directly; a socket server gives every process one shared database. Tests use in-memory PGlite with the real migrations, so no service is needed in CI.               |
| Driver selection  | `DATABASE_URL` decides: a `neon.tech` host uses `@neondatabase/serverless` over HTTP; anything else uses `pg`. Same Drizzle schema either way.                                                                                                                                                                                                                              |
| Package type      | ESM (`"type": "module"`) so `tsx` scripts can import the database client.                                                                                                                                                                                                                                                                                                  |
| Authorization     | Guards in `src/lib/authz.ts` throw a typed `AuthzError` (401/403/404); `withAuthz` and `withAuthzRoute` convert it. Missing resources are 404, someone else's are 403. The ESLint rule `bloom/require-authz` requires a guard in every `"use server"` export and API route method; `publicRoute` / `publicAction` mark the few intentionally open ones (health, login, signup, logout). |
| Route protection  | `src/proxy.ts` (Next 16's replacement for middleware) using the proxy-safe Auth.js config. JWT sessions carry `userId` and `role`, 12-hour max age, no database hit per request.                                                                                                                                                                                             |
| Passwords         | bcryptjs, 10 rounds. Student temp passwords are readable words (`maple-7482`), shown to the teacher once, never stored in plain text; `must_change_password` stays set until the student changes it (Phase 1 UI).                                                                                                                                                              |
| shadcn            | v4 (Base UI). The old `form` component no longer exists; `field` is its successor. `toast` is Base UI's toast.                                                                                                                                                                                                                                                              |
| Design tokens     | PLAN.md §5 colors as CSS variables wired to shadcn's semantic tokens: `primary` = coral for buttons, `sidebar` = teal, `ring` = teal, radius 8px. Inter (body) + Lexend (headings) via `next/font`. Light-only until Phase 3.                                                                                                                                                |
| Prettier          | Excludes Markdown after it rewrote spec text (`/app/*` became `/app/_`).                                                                                                                                                                                                                                                                                                   |
| Typecheck         | `next typegen` runs before `tsc` because Next 16 generates global types such as `LayoutProps`.                                                                                                                                                                                                                                                                             |
| `updated_at`      | One trigger function applied to every table with the column (migration `0001`); re-run its DO block after adding tables.                                                                                                                                                                                                                                                   |
| Media storage     | Cloudflare R2 via the S3 SDK. Browsers PUT straight to a presigned URL (10 min, owner-namespaced UUID key), then the server verifies with HEAD and records `media_assets`. Files are served through `/api/media/<key>` to signed-in users unless `R2_PUBLIC_URL` is set. Limits: images 10 MB, video 200 MB, audio 30 MB. Tests run against an in-memory S3 stub (`src/test/s3-stub.ts`), so R2 credentials are only needed to use uploads, not to test them. |
| Shared stimuli    | A stimulus is a course-level row (text, image, video, audio) referenced by `questions.stimulus_id`. Grouping is a pure helper (`src/lib/stimulus-groups.ts`): first-appearance order, one group per stimulus, contiguous. Pools carry `draw_stimulus_groups` so a draw can pull a whole group (used by the builder in 1.7). Deleting a stimulus that live questions use is refused; detach first. |
| Assessment build  | An assessment is sections of items; an item is one fixed question (optional points override) or "draw N from pool". Serving is a pure, seedable library (`src/lib/assessments/serve.ts`): section order kept, fixed items in order unless randomized, pool draws avoid questions already served, stimulus groups stay contiguous. Questions and pools must be on the assessment's course; fixed questions come only from banks the caller owns or is shared. Publishing needs at least one item; unpublishing and deleting are refused while assignments exist. Duplicate copies structure into an unpublished assessment the caller owns. The builder uses up/down buttons instead of drag so it works on a touchscreen. |
| Assignments       | One row per assessment × class, owned by the assigning teacher (who must own the class and own or hold a copy/co_edit share on a published assessment). Window times are typed in the browser's zone and stored as UTC; the browser sends its offset. Status is derived, never stored: scheduled / open / closed. Students see open assignments, scheduled ones as "opens soon", and closed ones only when they have work in them; the access code never reaches the student query. Accommodations (extra time %, font scale %) live on the enrollment so they apply to every assignment in the class. An assignment with attempts is closed rather than deleted. |
| Attempts          | `src/lib/attempts.ts` is the only writer of scores: `createAttempt` stores the exact served set (pool draws avoid questions the student saw on earlier attempts; option order shuffled for choice types when the assessment says so and always for ordering/matching) and `due_at` = start + limit × (1 + extra time %), capped at the close. `finalizeAttempt` grades every served question with the pure library (blank = wrong), writes responses, attempt totals, per-target scores, and recomputes the highest-counts final score; it is idempotent so later manual grades and overrides can call it again. Student actions save answers and flags only; saves are refused after `due_at` + 5 s grace or after submit. The test screen is one question at a time (`one_at_a_time` is reserved for a scrolling mode later); backtracking off hides Previous and the navigator. The runner never receives correct flags, explanations, or match keys. A student payload includes the server time so the countdown is anchored to the server clock; the client autosubmits at 0:00 and the server accepts a late submit but never a late save. Tab switches are counted via `visibilitychange` and shown to the teacher. |
| Grading & results | Manual grades and overrides both live in `responses.manual_score` (+ `grader_note`, `graded_by`, `graded_at`); a manual score beats the auto score, and clearing it restores the auto score. Every change calls `finalizeAttempt`, so attempt totals, per-target scores, and the highest-counts final score are never stale. The grading queue is "responses with no auto and no manual score on finished attempts", oldest first. The export is one row per enrolled student with the counting score (blank when they have no finished attempt), CSV, last name first, for Skyward entry. Correlated subqueries in a join-free select must reference the outer table by name (`attempts.id`), because drizzle renders unjoined columns unqualified. |
| Join codes        | Jon approved student self-registration (previously parked) in the form of class join codes. A class has a `join_code` (readable prefix + 4 unambiguous characters, rotatable, `join_open` toggle) and a list of expected names (`roster_names`). At `/join` a student enters the code, claims an unclaimed name (or types one, which is flagged `self_entered` for the teacher), and sets a password; the account gets a `username` (`first.last`, numbered on clashes) and no email. `users.email` is nullable and login accepts email or username. A signed-in student can add another class with its code from the student home. Teachers can still add students by email as before. |
| Corrections       | Ticket 1.11. A correction row per (attempt, question) with status `draft` → `submitted` → `approved` / `returned`; drafts autosave as typed and `submitted_at` is null until the final submit. Scope is a pure rule (`src/lib/corrections.ts`): formatives need every missed item, summatives only missed items in targets below the threshold (plus opted-in targets from `retake_gates`, Ticket 1.12); practice never; a response still awaiting a manual grade is not "missed" yet. Completeness: an answer plus a two-sentence explanation that does not lift the question's explanation (or any option's feedback) verbatim, checked server-side because the student payload never carries those texts; the form shows the hint (per-option feedback for the picked option, else the grader's note) and never the key. Review gate per assignment: `auto` approves at submit, `teacher_approved` parks the set in /app/results/corrections (one card per attempt; A approve, R return with a required note; returning reopens the set for editing). `startAttempt` refuses a new attempt while the last finished attempt's corrections are not approved. `ai_flag` is stored and shown but never set in Phase 1. |
| Practice & activities | Ticket 1.13. Practice sets are fixed questions or a pool draw; each attempt grades every answer the moment it lands (`src/lib/practice.ts`), one answer per question, complete when all are answered, best % kept. Activities complete by kind (`src/lib/practice-rules.ts`): video ≥90% of seconds actually played (seeks don't count), reading scrolled to the end + confirmed, link opened + confirmed (optionally teacher-verified), guided notes every prompt answered. Completions recompute the student's gates; publishing or pinning recomputes the course's. A student's content comes from the courses of their classes *and* of assessments given to those classes (`studentCourseIds`), so gates and visibility agree. |
| Worksheets        | Ticket 1.14. `POST /api/integrations/worksheet` is public by design, authenticated by `X-Bloom-Secret` (constant-time compare). Events are idempotent on (worksheet, email, at); unknown emails are kept as unmatched and can be linked to a student, which sets that student's email. A registered worksheet has a linked practice set and/or worksheet-kind activity; a submit becomes a completed practice attempt (`answers._worksheet`) and an activity completion, crediting only the targets whose mapped section scored when a section → target map exists. A worksheet registered by student link carries `pending:<url>` as its script id until the first webhook. |
| Tier board        | Ticket 1.15. The board is computed on each read from finals, gates, corrections, and attempts; the page polls `/api/results/[id]/tiers` every 7 s and re-renders only when a version stamp (newest change across those tables) moves. `assignment_final_scores.previous_tier` / `tier_changed_at` record each tier change for the "moved up today / this week" markers. |
| Sharing           | Ticket 1.16. Share by teacher email at view / copy / co_edit; every bank and assessment write already passes `requireShared(..., "co_edit")`. "Copy to mine" makes a new bank (questions + options, tags remapped by target code onto the chosen course; units and stimuli stay behind) or a draft assessment (sections remapped by code, items pointing at the same questions and pools). |
| AI import         | Ticket 1.17. A .pdf goes to Claude (`claude-opus-5`) as a document block; .docx via mammoth; structured output in the Appendix A row shape; rows enter the same preview-and-confirm wizard as a CSV. 10 MB and 20 calls/teacher/hour; every call logged to `ai_usage`. |
| Units in answers  | Sept 29, 2026. A typed unit never costs the point on its own: ignored when the key has no unit, matched with aliases (Seconds → s, cc → cm³, degrees C → °C) when it has one. The importer's two `unit` columns parse as `unit` (course) and `unit_2` (measurement). Results pages have Regrade to re-run auto grading after a key fix. |
| Retakes           | Ticket 1.12. Formative: `startAttempt` makes a fresh attempt of the same assessment (re-randomized per its settings) once the last attempt's corrections are approved; the card shows "Retake available" while attempts remain and the best score is under 100%. Summative: `retake_gates` rows (one per student × assignment × target) are recomputed by `src/lib/gates.ts` after every event (`recomputeFinalScore`, corrections submit/approve/return, opt-in) and lazily on first read when none exist. required = target percent below the assignment threshold; the student may opt into proficient targets when the assignment allows optional retakes. Gates: corrections_ok = every missed item on the latest attempt covering the target has an approved correction; activity_ok / practice_ok = a completed published item tagged to the target (the pinned one when pinned), and **true when nothing is published for that target**, so the gate never blocks on content that doesn't exist. The retake starts only when every selected target's gate is open and serves `scope` = selected target ids (new pool questions, same draw count); `computeFinalScore` already takes the max per target. Card order: corrections → relearning (a selected gate closed) → Retake required → Retake available → Done. |
| Teacher unlocks   | Jon, Oct 1 2026 (Anatomy formatives: 3 tries, best counts, a day between, taken in class). Per assignment, "Retakes need my OK" (`assignments.retakes_need_unlock`) makes every attempt after the first wait for an `attempt_unlocks` row (assignment × student × attempt number), written only by the owning teacher from the results page (Unlock attempt N / Take back). `canStartAttempt` refuses with `needs_unlock`; the student card shows "Waiting for teacher". A student may open the row themselves as a request (`requested_at` set, `granted_at` null; `requestRetake`): it unlocks nothing until the teacher approves it, which is the same `unlockNextAttempt` upsert; Decline = `revokeAttemptUnlock`. Pending requests queue on the dashboard and next to the student on the results page. With the setting on, corrections never gate the retake (they stay available and optional); the wait-between-attempts rule still applies on top of the unlock. |

| Deleting attempts | Sept 30, 2026. A teacher can delete any single attempt from the gradebook row or the attempt review page (two clicks; not undoable), for the case where a student starts the test again by accident. `deleteAttempt` in `src/lib/attempts.ts` is the only path: responses, per-target scores, and corrections cascade; later attempts move down a number so attempt 1 stays the first; the final score and retake gates recompute from what is left (no finished attempts = no final score, no gates). The student test screen goes back to the assignment page when a save or submit returns 404, so the student sees "Not started" and can begin again. |
| View as student   | Jon, Oct 1 2026. From a class roster, "View as" sets a two-hour cookie (`bloom.view-as` = student|class); `getCurrentSession` resolves it through `resolveViewAs`, which swaps in the student only when the signed-in teacher owns a class they are enrolled in, and marks the session `viewingAs`. `withAuthz` refuses every action under a borrowed identity, so the view is read-only; `stopViewAs` (public: it only clears the viewer's own cookie) returns to the class page. `proxy.ts` keeps a viewing teacher on the student pages. The practice-student follow-up (an account the teacher can act as, hidden from results) is not built yet. |
| Class review      | Jon, Oct 1 2026. `/app/results/[id]/review` is the projector view of item analysis: `getClassReview` extends `getItemAnalysis` with, per question, every option and how many finished attempts picked it (multi-select counts each pick), or the most common typed answers grouped case-insensitively (up to 6) with the key, plus blanks. The page starts on questions under 50%, one at a time, answers hidden until "Reveal". "Questions under 50%" stays on the results page for reflection; its "Edit question" links (and the review page's) carry `?back=` so the question editor returns there on Save, Cancel, or the back link (same-site `/app` paths only). |
| Class order       | Jon, Oct 1 2026. `classes.sort_order` holds the teacher's own order for the Classes page: drag a card (or pick Sort by period / name / course / newest, which writes that order) and `reorderClasses` stores the index of every id; `listClasses` orders by it, then by the digits in `period`, then name, so classes that were never dragged still fall into period order. |
